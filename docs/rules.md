# 规则说明

规则写在工作目录的 `rules.json` 里。没写的项用默认值（见 [rules.example.json](../resume_screener/data/rules.example.json)）。

## 两道闸

| | 快筛 | 规则判定 |
|---|---|---|
| 什么时候 | 调模型之前 | 模型解析之后 |
| 看什么 | 简历原文 | 模型解析出的结构化信息 |
| 目的 | 明显不合格的不调模型，省钱 | 最终结论 |
| 查哪些 | 教育经历段里的排除关键词、专科 | 专科、专升本、非全日制 / 非统招、公司黑名单、院校清单 |

共同原则：简历没写清楚的默认放行，只有明确不符合才淘汰。

## education：学历

```json
"education": {
  "block_associate": true,
  "reject_part_time": true,
  "reject_upgrade": true,
  "exclude_keywords": ["非全日制", "自考", "函授", "专升本", "网络教育"]
}
```

**`block_associate`**：最高学历是专科的淘汰。

- 快筛阶段只认带上下文的写法：「最高学历：大专」「大专毕业」「三年制专科」，或者教育经历段里只有专科没有本科及以上。
- 「岗位要求大专及以上」「在高职院校授课」这类只是提到，不会被淘汰。
- 模型解析后 `highest_degree` 是「专科」的也淘汰。

**`reject_part_time`**：模型明确判定非全日制（`is_full_time` 为 false）或非统招（`is_zhengshou` 为 false）的淘汰。模型没法判断时这两项是 null，按通过处理。

**`reject_upgrade`**：模型判定为专升本的淘汰。

**`exclude_keywords`**：快筛用。这些词出现在「教育经历」这一段里就直接淘汰。

- 只在教育经历段里找，不搜全文。做人力资源的候选人在工作内容里写「负责非全日制用工管理」，不会被误杀。
- 截不到教育经历段（简历没有这个小节标题）时，快筛不判，交给模型。
- 是子串匹配，所以别放太短、容易撞上的词。比如「成教」会撞上「完成教学任务」。

想完全关掉学历规则：三个开关设成 `false`，`exclude_keywords` 设成 `[]`。

## schools：院校清单

```json
"schools": {
  "require_in_list": true,
  "list": "院校清单.csv",
  "groups": [],
  "aliases": "校名别名.json",
  "xlsx_name_column": 1,
  "xlsx_first_row": 2
}
```

**`require_in_list`**：最高学历的毕业院校必须在清单里。只看最高学历那一段，本科院校不单独要求。设成 `false` 就不查院校，也不需要清单文件。

**`list`**：清单文件，相对于工作目录。两种格式：

`.csv`（或 `.txt`），每行一所，第二列是可选的分组：

```text
# 井号开头的是注释
校名,分组
北京大学,国内
麻省理工学院,海外
```

`.xlsx`，每个工作表算一个分组，分组名就是表名。校名在第几列、从第几行开始，用 `xlsx_name_column` 和 `xlsx_first_row` 指定（都从 1 数起）。

**`groups`**：只用清单里的某几个分组。空数组表示全部都用。

**`aliases`**：自定义别名表，一个 JSON 文件，左边是简历里可能出现的写法，右边是清单里的校名。主要用来补外文校名和旧校名：

```json
{
  "National University of Singapore": "新加坡国立大学",
  "华中理工大学": "华中科技大学"
}
```

### 校名是怎么匹配的

依次尝试，任何一步对上就算在清单里：

| 步骤 | 例子 |
|---|---|
| 完全一致 | 「清华大学」 |
| 内置的常见简称 | 「北大」→ 北京大学，「华科」→ 华中科技大学 |
| 去掉括号注记 | 「麻省理工学院（美国）」「浙江大学（玉泉校区）」 |
| 自定义别名表 | 「Stanford University」→ 斯坦福大学 |
| 中英文连写取中文部分 | 「澳大利亚国立大学Australian National University」 |
| 简历多写了二级学院 | 「华中科技大学同济医学院」「北京大学光华管理学院」 |
| 简历少写了几个字 | 「北京航空航天」（至少 5 个字） |

简称只是帮助匹配，合不合格仍然看全称在不在你的清单里。「复旦」能认出是复旦大学，但清单里没有复旦大学的话照样不通过。

### 独立学院不算本校

「××大学 + 后缀」的情况，后缀是学科类的二级学院才算本校：

| 写法 | 结果 | 原因 |
|---|---|---|
| 华中科技大学管理学院 | 算 | 学科类学院 |
| 北京大学法学院 | 算 | 学科类学院 |
| 北京大学深圳研究生院 | 算 | 研究生院 |
| 广东工业大学华立学院 | 不算 | 独立学院 |
| 浙江大学城市学院 | 不算 | 独立学院 |
| 华中科技大学文华学院 | 不算 | 「文华」不是学科名 |
| 北京大学继续教育学院 | 不算 | 继续教育 |
| 华中科技大学网络教育学院 | 不算 | 网络教育 |
| 华中科技大学附属中学 | 不算 | 不是高校 |

判断依据是后缀里有没有学科名（医、管理、计算机、外国语……）。单个字的学科名（文、理、工、商、法、农、林）必须整词出现：「文学院」算，「文华学院」不算，「理工学院」也不算。

拿不准某个写法会怎么判，用命令试一下：

```bash
python3 -m resume_screener -w my-workspace check-school "浙江大学宁波理工学院"
```

## company_blacklist：公司黑名单

```json
"company_blacklist": ["某某重工", "某某科技"]
```

候选人的工作经历里，公司名包含列表中任何一项的淘汰。默认是空的。

- 只查模型解析出的工作经历里的公司字段，不搜全文。「负责与某某重工的竞标分析」「参与某某重工项目交付」不会被淘汰。
- 是子串匹配：写「某某重工」能匹配「某某重工股份有限公司」。同一家公司有多个叫法的话都列上。
- 因为依赖模型解析，这条规则不在快筛里执行。

## match：JD 反选

```json
"match": {"allow_gender_filter": false, "allow_age_filter": false}
```

JD 反选时，模型会从岗位要求里读出这些硬性条件：学历下限、经验年限下限、工作地点、性别、年龄范围。

- 学历、年限、地点始终生效。候选人的年限或所在地未知时放行；学历未知时淘汰。
- 性别和年龄默认**不**生效。JD 里写了也会被忽略，并在结果里注明「没有用来筛选的条件」。把对应开关设成 `true` 才启用；启用后，候选人这一项未知的仍然放行。
- 地点支持「JD 写省、简历写市」的对应。

软性打分的算法：

| 部分 | 权重 |
|---|---|
| JD 关键词被候选人关键词覆盖的比例 | 50% |
| 两边关键词的 Jaccard 相似度 | 30% |
| JD 关键词出现在「最近两段工作总结」里的比例 | 20% |

关键词按全等比较（不分大小写），所以这个分数只适合粗排。

## folders / output / rename：文件夹和命名

```json
"folders": {"inbox": "简历/待处理", "passed": "简历/通过", "rejected": "简历/淘汰", "failed": "简历/失败"},
"output": {"summary_xlsx": "输出/汇总表.xlsx", "log_file": "输出/处理日志.log"},
"rename": {"format": "{name}-简历-{ts}", "ts_pattern": "%Y%m%d-%H%M%S"}
```

路径都相对于工作目录。处理过的简历会被**移走**（不是复制），所以同一份简历不会被处理两次；想重新处理，把文件放回「待处理」。

汇总表可以手动调整列的顺序、加自己的列，程序按表头名找列，不会写错位。不要改表头的名字。
